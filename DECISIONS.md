# DECISIONS

Every scope cut / deviation from the master plan. One line + rationale. Newest first.

- 2026-09-30 — **The MCP surface grows from five tools to nine: discovery tools, and a topology that lists identities only.** Master plan §3.2 names five tools. The first real runs showed an agent cannot diagnose without knowing what telemetry exists: 8 of 10 PromQL queries used guessed names and returned nothing. `list_metrics`, `list_metric_labels`, `list_log_labels` and `list_trace_tags` answer that, the way a metric browser does for a human; they cap and sort their lists (the only place the server shapes an answer), since thousands of metric names would fill a model's context. `get_k8s_topology` is now implemented with read-only `kubectl get` and lists Deployments, StatefulSets and DaemonSets by kind, namespace and name — never status, so which workload is broken still has to come from the telemetry — plus the trace-derived service graph. In bench runs it hides objects labeled `managed-by=argus-bench`: the fault apparatus is not the system under diagnosis. Tool descriptions carry neutral syntax examples (`my-service`), never names from the environment; a test enforces it.
- 2026-09-30 — **The flagship benchmark uses local models only.** Master plan §2 asks for three agents including a frontier and a budget API model. The maintainer's runs are `--local-only` (no paid APIs, no keys), so the flagship matrix will compare two or three locally served models instead. Measured on kind: one run is about 4 to 5.5 minutes and 50k to 90k tokens, so the floor matrix (8 scenarios × 3 repeats × 2 conditions = 48 runs) is roughly 4 to 6 hours of GPU time per model and no API spend. The harness still supports any OpenAI-compatible or Anthropic endpoint; only the published comparison is local. A second local model is needed, which also unblocks the judge (B-32).
- 2026-09-30 — **Fault categories are a closed list the agent is shown.** The category is half the default score and is matched exactly, and the first real run answered `PerformanceDegradation` against a ground truth of `deploy-regression`: it had never seen the vocabulary. `scenarios/categories.yaml` now holds the list, with a one-line description each and more categories than scenarios. Every agent gets it as an enum on `submit_diagnosis` and in the brief, sorted by name. Rejected: dropping the category from the score (the right workload for the wrong reason would then be a full answer), and mapping free text with an LLM (scoring would stop being deterministic). `bench run` refuses to run without a list.
- 2026-09-30 — **The degraded-vs-remediated comparison counts only scenarios answered under both conditions, and a telemetry condition is a label.** `bench report --compare` excludes a scenario that is missing or unanswered on either side and lists it with the reason, instead of scoring it zero: the run reports already treat a failed run as no answer, and zero-filling here would turn an agent that stopped answering into a large Δ of our own making. The answer rates under each condition are printed beside the means for that reason. No significance test is applied; the spread and run counts are shown. `--condition` only records what the operator says the environment's state was: Argus is read-only and does not put the environment into a condition or verify it (master plan §5, rule 6).
- 2026-09-30 — **A bench agent is told its budget, and gets one turn to submit when it is spent.** The first live run against a real model used all 20 tool calls investigating and was cut off without a diagnosis: nothing had ever told it a limit existed. A cap the subject cannot see measures whether it happens to stop early. The brief now states the caps; when the last permitted tool call is used the agent is told, and its next turn must be `submit_diagnosis`. Calls past the cap are refused, not executed and not counted, so the enforced budget is unchanged. Shell agents receive the caps as environment variables, since Argus cannot enforce them there.
- 2026-09-30 — **Run reports keep a tool log, without the answers.** Each executed tool call is recorded with its arguments (truncated) and any error; results are raw telemetry, so only their size is kept. Without it, a run with no diagnosis could not be told apart from one whose tool surface was failing. The category an agent gave is recorded verbatim for the same reason.
- 2026-09-30 — **Releases are built by CI but published by a person.** A tag produces a *draft* GitHub release with all assets; the notes are pasted by hand and a maintainer publishes. Generated changelogs would drop the positioning and fidelity caveats every release note carries. The plugin zip is signed only when a `GRAFANA_ACCESS_POLICY_TOKEN` secret exists and otherwise ships unsigned with a workflow warning, so a missing secret cannot block an engine release.
- 2026-09-30 — **§6.5 "deploy regression (bad image)" ships as a bad-config rollout.** With one replica and a RollingUpdate, an unpullable image never replaces the healthy pod: the surge pod sits in ImagePullBackOff while the old one keeps serving, so nothing breaks. Forcing `Recreate` would produce an outage whose signal is identical to `oomkill-checkout`'s absence. Pointing cart's `VALKEY_ADDR` at a closed port keeps what the scenario is about: the rollout succeeds, then every request through the changed workload fails, and the errors name a healthy dependency.
- 2026-09-30 — **Environment-variable faults record the original on the Deployment and are restored namespace-wide.** `faults/lib/env-fault.sh` stores the original entry (a literal, a `valueFrom` reference, or the variable's absence) as an annotation before patching. `faults/restore-all-mutations.sh`, which is the reset and cleanup of every mutation scenario, restores every recorded mutation, not only the scenario's own. It is the mutation counterpart of the label sweep, so a mutation leaked by a crashed run cannot sit under another scenario's baseline. A test requires every scenario that uses the helper to use that hook.
- 2026-09-30 — **§6.5 "DNS failure" ships as an egress blackhole.** DNSChaos does not inject on this cluster (chaos-mesh 2.8.3's helper panics rewriting resolv.conf; `AllInjected=False`). A directional NetworkChaos partition from frontend to three backends gives the same diagnostic shape — a broken caller blaming healthy callees — through a mechanism that verifiably injects.
- 2026-09-30 — **§6.5 "network policy block" ships as a Chaos Mesh partition.** kind's default CNI (kindnet) does not enforce NetworkPolicy, so the object would be created and block nothing, scoring agents against an un-faulted cluster. Worth adding a NetworkPolicy variant for Calico/Cilium clusters.
- 2026-09-30 — **The OOMKill scenario lowers checkout's own memory limit** instead of running a stressor beside it. StressChaos injected, but the OOM killer took the stressor (the largest process in the cgroup) and checkout never restarted. The script records the original limit and rollout strategy on the Deployment and switches it to `Recreate`, since a single-replica RollingUpdate keeps the healthy pod alive and the fault never bites; a restore hook puts both back.
- 2026-09-30 — **Reset sweeps every `managed-by=argus-bench` object, cluster-wide**, not only the current scenario's manifests. A StressChaos applied by hand during July's validation sat on checkout for two months, restarting it repeatedly; a scenario's own cleanup cannot see another's leftovers, and the baseline check only watches the current scenario's signature.

- 2026-09-30 — **Product vs. maintainer setup split for local inference.** The project rules said "no GPU, no CUDA, no local model hosting anywhere", while the bench work (PR #61) shipped a CUDA-tuned Ollama Modelfile and made `--local-only` the default for everyone. Resolved by the user: Argus the product never hosts models, loads weights or drives a GPU — it only speaks HTTP to an endpoint. `--local-only` becomes **opt-in**, so other users can bench remote APIs as the master plan intends, and the maintainer's no-paid-API guarantee is set explicitly on their own runs. `deploy/ollama/` stays as operator tooling for an external process. Rejected: keeping local-only as everyone's default (blocks a primary documented use case), and deleting the Ollama tooling (discards a working 46 tok/s setup and the main reason the served-context guard exists).
- 2026-09-30 — Open work moved into **`BACKLOG.md`** with stable IDs, next to this file. Nothing tracked it before, and a two-month gap in sessions was enough to lose track of what was broken versus merely unmerged. Chosen over GitHub Issues by the user: reviewed in a PR, nothing public until it merges.
- 2026-09-30 — **Correction to the 2026-07-25 scenario-1 retarget.** It said checkout "emits only Go runtime metrics plus `target_info` — 10 series, no request metrics". That was read off a cluster about ten minutes old; nine hours later checkout emitted 226 series including `rpc_server_*`/`rpc_client_*`. Request metrics appear once a service has served traffic. The retarget still stands, for a different reason: checkout's request metrics are **bounded** (its only per-request dimension, `rpc_method`, has one value), so there is nothing to explode. Lesson recorded in docs/bench/scenario-01-validation.md: validate a ground truth against a warm cluster.
- 2026-09-30 — **A bench repeat may only inject into a verified-clean environment.** Before injecting, the orchestrator waits until the scenario's steadyState signature is observably *absent*, and fails the repeat with a "baseline" error if it never is. Without this, repeats were not independent: frontend's OTel SDK keeps every series a fault created in memory after cleanup, so repeat 2 passed its gate on repeat 1's leftovers. Rejected: patching only the probe's leaked settle timer, which fixed a symptom and left repeats scoring stale telemetry. Scenario 1 therefore needs a reset that restarts frontend before `--repeats >1` can succeed (BACKLOG B-10); until then it fails loudly instead of silently.
- 2026-09-30 — **A malformed evidence citation is not counted, rather than failing the diagnosis.** Failing it made the run a normalization failure, which the summary excludes from the mean — so citing garbage *raised* an agent's average. Now the citation is dropped (and reported as malformed), and a diagnosis left with none scores 0 under `requireEvidence` like any uncited answer.

- 2026-07-25 — _(Reasoning corrected 2026-09-30, see above; the decision stands.)_ Scenario 1 **retargeted from checkout to frontend**, and renamed accordingly. Live validation showed otel-demo checkout (Go, chart 0.40.9) emits only Go runtime metrics plus `target_info` — 10 series, no request metrics — so no traffic can explode its cardinality; the original premise was unachievable, not merely unverified. frontend emits `app_frontend_requests_total` whose `target` label carries the raw URL path, so an unbounded path parameter produces one series per request (measured: 60 unique paths → exactly 60 new series). Rejected alternative: keeping checkout by patching its instrumentation, which would be changing the application rather than injecting a fault.
- 2026-07-25 — Manifest-based faults must be **additive-only**. The kubectl injector applies on inject and runs `kubectl delete -f` on reset/cleanup, so a manifest patching an existing workload would inject correctly and then be "cleaned up" by deleting the real Deployment. Faults needing mutation of a pre-existing resource stay `script` steps (as `toggle-flag.sh` already is). Documented in the manifest header and the bench guide.
- 2026-07-25 — Bench scoring folds category match into an overall `score` (default weight 0.5), requires cited evidence when the scenario asks for it, and penalizes named decoys (default 0.25 each). Calibration with a canned stub showed the previous rubric gave a flawless 1.00 to an evidence-free guess of the most conspicuous workload. Evidence is checked for presence and form, **never for truth** — verifying an observation would mean re-running the agent's queries — so a fabricated citation still scores; that ceiling is asserted by a test and printed in every report.
- 2026-07-25 — _(Superseded 2026-09-30: `--local-only` is now opt-in, see above.)_ Bench runs are **local-inference-only by default** (`--local-only`): loopback endpoints required, API keys refused, judge model must differ from the agent model. Endpoints are refused by hostname literal without DNS resolution, since a name resolving to loopback today can resolve elsewhere tomorrow. Rationale: a benchmark that can silently bill a paid API is a defect, and one model grading its own output launders its errors into the score.
- 2026-07-25 — `deploy/ollama/Modelfile.qwen3.6-bench` pins **`num_gpu 26`** (26 of 40 layers on GPU, rest in RAM). The model is ~22 GiB at Q4_K_M against a 16.3 GB card; Ollama's automatic sizing over-commits and dies with `CUDA error: shared object initialization failed`, which looks like a driver/Blackwell incompatibility but is not — an explicit layer count works. Measured 2.4 tok/s CPU-only, 46.1 at 26 layers, 48.8 at 28, and **6.1 at 30** (thrashing, reported as no error at all). 26 trades ~5% throughput for ~1.1 GB of VRAM headroom because the cliff is silent and an unattended matrix that tips over wastes hours without saying why.
- 2026-07-25 — Agent HTTP timeout raised from a hardcoded 60s to 10m (`--agent-timeout`; judge 5m), after a live run died mid-investigation at 15 tool calls with `Client.Timeout exceeded` and was recorded as an agent failure. Local inference on CPU/partial-offload routinely spends minutes on one turn; the old default made the default configuration unusable.
- 2026-07-25 — Tool-call budget accounting fixed: both API adapters incremented before checking, so a run capped at 12 reported 13, counting a refused call. Every budget-exhausted leaderboard row would have overstated consumption.
- 2026-07-25 — `argus bench run` probes Ollama's `/api/show` and **aborts below `--min-context`** (32768). `ollama pull qwen3.6:35b-a3b-q4_K_M` yields a model with a 262144 architectural context but no `num_ctx` parameter, so it is served at the runtime default and truncates the tool surface silently. `deploy/ollama/Modelfile.qwen3.6-bench` sets it explicitly. Sampling left at the model's recommended values — Qwen thinking models loop at temperature 0, which would read as agent incompetence.

- 2026-07-18 — **Backtest v0.3 evaluates by query stepping, not embedded promql engine**: the spike's live baseline re-run measured replay-vs-live divergence at ±1 evaluation step with `for:` durations exact and zero missed/extra firings (both direct and synthesize modes); step alignment is a caveat we can state honestly, while engine embedding adds a large surface (storage adapters, staleness internals) for sub-step accuracy the caveat already bounds. Spike closed 5 days inside its timebox.
- 2026-07-17 — Spike (b) live-divergence quantification postponed to a re-run: the dev cluster was deleted before the 20:00–22:00Z block was cut, losing the first experiment's telemetry + ALERTS baseline with the WAL (Phase 0's documented ~2h-WAL-loss acceptance). Kept the incident in incidents.yaml as the canonical unverifiable incident; replay was instead validated against surviving preserved blocks via a read-only MinIO+Mimir stack (28 instant vs 1 for:5m firings over 1h14m covered history).
- 2026-07-16 — v0.2 ships illustrative ingest/active-series rates in the pricing templates (user call: honesty-over-polish): S3 storage classes use real AWS list prices, but self-hosted compute has no invoice to copy, so those rates are inherently modeled. Instead of pretending otherwise, a second standing caveat ("shipped template rates are illustrative — calibrate pricing.yaml") now rides on every cost rendering (Markdown, JSON, Spend page) alongside modeled-not-billed, so no screenshot can present a modeled number as a billed one.
- 2026-07-15 — Soak-4 ended at 10.3h instead of the planned 24h (user call: machine can't stay on overnight). All success criteria were already green — memory flat +1.6% post-warmup, rotation observed, zero evictions/receiver errors/pod restarts, continuity continuous across 611 samples — so the calibrate proposal was regenerated from this run rather than waiting for a full 24h window. A longer unbroken soak remains preferable before trusting MET-001/SPA-003 proposals beyond demo-fleet scale.
- 2026-07-15 — Golden runner now routes inputs through the REAL ingest pipeline (trackers, fixed clock advanced one window) instead of feeding the collector directly: the orphan false positive lived exactly in the gap between rule goldens (synthetic aggregate rows) and tracker unit tests. New cross-service-trace golden (child in payment, root in frontend) pins zero SPA-002/ARG-SPA-002 findings; six existing goldens gained the tracker-emitted passing results their scores now honestly include.
- 2026-07-14 — TraceTracker rewritten to key traces GLOBALLY by trace ID (was per service,trace): the 2.5h soak showed every downstream service scoring orphan/missing-root 1.00 because parents and roots lived in other services' fragments. Orphans/rootlessness now attribute to the break-point services (dangling parent references), falling back to all participants only when caps hide the break. Memory envelope roughly doubles worst-case (still capped); documented in rule pages.
- 2026-07-14 — Collector aggregate-rule state changed from append-per-tick violation slices to counters + latest-wins evidence ring (MaxEvidence): the soak caught RSS +38%/2.5h from unbounded aggFindings growth in serve mode. Aggregate finding evidence now shows the LATEST rows, not the first ones.
- 2026-07-14 — Rule schema gained an OPTIONAL `calibration:` block (param/source/aggregate/field/kind) tying one params key to the distribution that informs it — the data-driven alternative to hardcoding rule→distribution mappings inside the calibrate command; additive, strict-loader-validated, no existing rule file becomes invalid. Flagged per the no-silent-schema-changes rule.
- 2026-07-14 — `calibration.param` may be the dotted literal `service_violation.threshold_ratio`: ARG-LOG-001's threshold is the item-rollup ratio, which lives outside `params`.

- 2026-07-20 — ITBench import is **score-only**: ITBench executes faults via its own tooling against a fixed fault-id catalogue, which Argus cannot reproduce. Imported scenarios emit a deliberately non-executable inject script so they fail loudly unless run with `--inject=none` (ITBench stages the environment; Argus scores the agent). Rejected alternative: hand-translating the 30 upstream fault ids into Argus manifests — our translation would not be ITBench's fault, which would make the comparability claim false.
- 2026-07-20 — ITBench ground truth is derived from each injection's `args.kubernetesObject`; `waitFor` waiter objects (restarted/rescaled workloads) are excluded as collateral. A scenario with no derivable entity is **refused**, never emitted with empty ground truth (which would score every agent answer wrong). `--skip-invalid` opts into continuing past such scenarios.
